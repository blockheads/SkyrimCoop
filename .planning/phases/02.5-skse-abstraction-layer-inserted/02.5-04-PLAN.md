    **ReplayBridge.h updates:**
    - Add data structures for canned responses: `std::unordered_map<std::string, std::vector<nlohmann::json>> m_queryResponses;` keyed by "op" name.
    - Add `size_t m_eventIndex = 0;` for sequential event replay.

    **ReplayBridge.cpp full implementation:**
    Per D-05 and D-06: ReplayBridge reads NDJSON file, parses each line, separates mutation events (dir=call only) from query events (dir=return entries contain the canned value).

    `LoadRecording(const std::string& aPath)`:
    1. Open file, read line by line.
    2. Parse each line as `nlohmann::json`.
    3. For lines with `"dir":"return"`: store in `m_queryResponses[op]` vector.
    4. For lines with `"dir":"call"` that are mutations (no corresponding return): store in `m_events` vector for sequential replay.

    `NextResponse(const char* apOp)`:
    1. Look up `m_queryResponses[apOp]`.
    2. If found and has entries, return and remove the first one (FIFO).
    3. If not found, return empty json.

    Implement ALL IActorBridge overrides:
    - Query methods (e.g., `ActorExists`, `IsActorDead`, `GetActorValue`): call `NextResponse("MethodName")`, extract "result" field, return typed value. Return false/0.0f if no response available.
    - Mutation methods (e.g., `SetActorRemote`, `KillActor`, `DeleteActor`): no-op (mutations were recorded for documentation, but ReplayBridge doesn't need to simulate their effects).

    Implement ALL IFormBridge overrides: Same pattern — queries return canned data from NDJSON, mutations are no-ops.

    Implement ALL IPlayerBridge overrides: Same pattern.

    Implement ALL IEventBridge overrides:
    - `RegisterQuestStartStopSink(...)`: Store the callback. Later, when `PumpEvents()` is called, synthesize events from the NDJSON file's event entries.
    - Add `void PumpEvents() noexcept;` method: iterates m_events, for event-type entries (e.g., quest start/stop), fires the registered callback with the recorded data.

    Implement ALL IWorldBridge overrides: Same pattern as queries.

    Per D-06: NDJSON schema is client-side event schema:
    ```json
    {"op":"ActorExists","formId":"0x14","dir":"call","ts":0.001}
    {"op":"ActorExists","formId":"0x14","dir":"return","result":true,"ts":0.001}
    {"op":"SetActorRemote","formId":"0x14","remote":true,"dir":"call","ts":0.002}
    {"op":"GetCurrentWeatherId","dir":"call","ts":0.003}
    {"op":"GetCurrentWeatherId","dir":"return","result":"0xA6858","ts":0.003}
    ```
