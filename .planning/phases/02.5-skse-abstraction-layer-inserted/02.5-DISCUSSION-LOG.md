## Interface Granularity

| Option | Description | Selected |
|--------|-------------|----------|
| Single ISkyrimBridge | One monolithic interface with all methods. Simple swap but could reach 50+ methods. | |
| Multiple focused interfaces | IActorBridge, IFormBridge, IEventBridge, etc. Each service depends only on what it uses. | ✓ |
| Single with logical sections | One class with methods organized into sections. Monolithic but readable. | |

**User's choice:** Multiple focused interfaces — one per logical grouping
**Notes:** "seems like a logical split, keep an interface for each logical grouping"

---

## Dependency Injection / Bridge Role

| Option | Description | Selected |
|--------|-------------|----------|
| World context | Store bridge in World via entt::registry::ctx(). Matches existing pattern. | |
| Constructor injection | Each service takes bridge ref in constructor. Explicit but more changes. | |
| Global singleton | ISkyrimBridge::Get() like World::Get(). Simplest swap. | |

**User's choice:** Deferred to Claude's discretion — "just follow whatever practices we have"
**Notes:** User's key point was not about the injection mechanism but the principle: "every single thing that calls into SKSE will need to get swapped to use the corresponding bridge... no services are exposed to SKSE... the bridge is the single caller to SKSE." The bridge is a hard wall — no service touches SKSE directly, period.

## Replay Data Format

| Option | Description | Selected |
|--------|-------------|----------|
| NDJSON with client schema | Same NDJSON format as server harness but client-side event types. Tooling reuse. | |
| Canned data / stubs | Hardcoded data for known form IDs. Simpler but less realistic. | |
| Recording + replay | Instrument SkyrimBridge to record all calls/returns to NDJSON, ReplayBridge plays back. | ✓ |

**User's choice:** Recording + replay
**Notes:** "the whole point for this is recording as well that's why we're doing this, for automated testing"

## Abstraction Scope / Rollout

| Option | Description | Selected |
|--------|-------------|----------|
| Critical path only | CharacterService + PlayerService + TransportService (~3 services). Small phase. | |
| All sync services | ~8 core sync services. Covers Phase 4 needs. | |
| Everything | All 24 service files. Complete abstraction, no tech debt. | ✓ |

**User's choice:** Everything — all 24 services
**Notes:** "let's do it all now, no tech debt later on, there's nothing complicated about this work, we have the entire SKSE source code available to us"
