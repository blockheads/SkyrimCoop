# Phase 02.5 Plan 03: High-Complexity Service Migration + Compilation Boundary Summary

**One-liner:** Migrated CharacterService (56 SKSE calls), MagicService, PlayerService, ObjectService to fat-bridge interfaces and confirmed SkyrimTogetherClientServices compiles with zero SKSE headers.

## Objective

Migrate the 8 high-complexity services (10-56 SKSE calls each) to bridge interfaces, then prove the compilation boundary by building SkyrimTogetherClientServices — a static lib containing all Services/Generic/ files but compiled without SKSE headers.

## What Was Built

### Task 1: CombatService, InventoryService, OverlayService, ObjectService Migration

Four medium-to-high complexity services migrated from direct SKSE API calls to bridge interface calls:

- **CombatService**: Combat target detection, attack state queries, process flags
- **InventoryService**: Item list extraction, equipment slot queries, worn item lookups
- **OverlayService**: Subtitle dispatch, HUD visibility toggling
- **ObjectService**: Open/close state dispatch via PreActivationOpenStateValue (SKSE-free)

Commit: `3032d6e0`

### Task 2: MagicService, PlayerService, CharacterService Migration + Compilation Boundary Proof

Three highest-complexity services migrated:

- **CharacterService** (56 SKSE calls, 1605 lines): Actor spawning, appearance serialization, faction sync, animation variable broadcast — all via IActorBridge/IFormBridge
- **MagicService**: Spell/shout cast dispatch, magic caster queries — via IActorBridge
- **PlayerService**: Player data sync, mod list enumeration, save/load hooks — via IPlayerBridge/IFormBridge

SkyrimTogetherClientServices xmake target added to xmake.lua — a static lib that compiles all Services/Generic/ files explicitly listed, without SKSE headers in the include path. This target building confirms D-02/D-03: all services use bridges and SkyrimBridge.cpp is the sole SKSE TU.

Commit: `36e2241d`

  - `#include <Magic/MagicItem.h>` — file is at `Games/Skyrim/Forms/MagicItem.h`

**2. [Rule 2 - Missing functionality] Added HAS_DIRECTXTK guards for SKSE-dependent utilities**
- **Found during:** Task 2 — Utils.h and World.h included SKSE-dependent code that would break SkyrimTogetherClientServices
- **Issue:** `Utils::GetByServerId` uses SKSE Actor* pointer, `World::DebugService` depends on SKSE types
- **Fix:** Wrapped both in `#ifdef HAS_DIRECTXTK` guards — only active in full SKSE builds, not in the boundary-proof services lib
- **Files modified:** `Code/client/Utils.h`, `Code/client/World.h`
- **Commit:** `36e2241d`

**3. [Rule 2 - Missing functionality] Added PreActivationOpenStateValue to ActivateEvent**
- **Found during:** Task 1 — ObjectService needed open/close state without TESObjectREFR::OpenState
- **Issue:** TESObjectREFR::OpenState is an SKSE type not available in the services boundary
- **Fix:** Added `uint8_t PreActivationOpenStateValue` field to ActivateEvent.h; TESObjectREFR.cpp populates it at event dispatch; services read it without SKSE dependency
- **Files modified:** `Code/client/Events/ActivateEvent.h`, `Code/client/Games/Skyrim/TESObjectREFR.cpp`
- **Commit:** `3032d6e0`
