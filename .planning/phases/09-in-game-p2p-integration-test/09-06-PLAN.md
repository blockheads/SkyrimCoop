<objective>
Fix Wine guest-to-host address translation for /proc/pid/mem reads.

Purpose: Hook trampolines in the relay DLL send raw Wine virtual addresses as uint64_t args. ProcMemReader::Read() passes these directly to pread(), which under Wine/Proton may require address validation. Currently every pointer-based game read returns zero or garbage, blocking all services that read formId, position, or health. This plan adds /proc/pid/maps parsing for address validation and diagnostic logging to identify whether Wine addresses are directly usable or require translation.

Output: ProcMemReader that validates addresses against memory maps, diagnostic logging for address reads, and either working pread() calls or clear diagnostic output showing the exact failure mode.
</objective>

Add memory map parsing and address validation to ProcMemReader. The goal is to diagnose and fix the Wine address translation issue.

**In proc_memory.h**, add:
```cpp
struct MemoryRegion {
    uint64_t start;
    uint64_t end;
    bool readable;
    std::string name;  // e.g., "SkyrimSE.exe", "[heap]", etc.
};
```

Add these methods to ProcMemReader:
```cpp
// Parse /proc/pid/maps and cache readable regions
bool LoadMemoryMaps();
// Check if addr falls within a readable region; returns region name or empty
std::string ValidateAddress(uint64_t addr) const;
// Log summary of mapped regions (call once after Open)
void DumpMemoryMapSummary() const;
// Get count of loaded regions
size_t GetRegionCount() const;
```

Add private member:
```cpp
std::vector<MemoryRegion> m_regions;
```

**In proc_memory.cpp**, implement:

1. `LoadMemoryMaps()`: Open `/proc/{m_pid}/maps`, parse each line. Format is:
   `START-END PERMS OFFSET DEV INODE PATHNAME`
   Example: `7f1234000-7f1235000 r-xp 00000000 08:01 12345 /path/to/SkyrimSE.exe`

   Parse start/end as hex uint64_t. Check perms[0]=='r' for readable. Store pathname.
   Log total regions found and specifically log any regions containing "SkyrimSE" or "skyrim" (case-insensitive).

2. `ValidateAddress(uint64_t addr)`: Linear scan m_regions, return region name if addr >= start and addr < end and region is readable. Return empty string if not found.

3. `DumpMemoryMapSummary()`: Log count of total regions, count of readable regions, and list all regions whose name contains "SkyrimSE" or "skyrim_coop" with their address ranges.

4. Modify `Open()`: After successfully opening the fd, call `LoadMemoryMaps()` and `DumpMemoryMapSummary()`.

5. Modify `Read()`: Before calling pread(), call ValidateAddress(addr). If the address is NOT in any mapped region, log at warn level: `"pread addr {:#x} not in any mapped region for pid {}"`. Still attempt the pread (the maps might be stale). If pread returns <= 0 AND the address was not validated, log at error level: `"pread failed for unmapped addr {:#x}: {} ({})"` with strerror(errno).

   If pread returns <= 0 but the address WAS in a mapped region, log: `"pread failed for addr {:#x} in region '{}': {} ({})"` -- this indicates a different problem (permissions, ptrace, etc).

This diagnostic approach will reveal whether:
(a) Wine addresses appear in /proc/pid/maps at all (if not, translation is needed)
(b) Wine addresses appear but pread still fails (permissions/ptrace issue)
(c) Wine addresses are valid and pread works (the issue was something else)

Include `<fstream>`, `<sstream>`, `<vector>`, `<algorithm>` headers as needed.

}

Change to:
```cpp
uint32_t GameReader::ReadFormId(uint64_t aFormPtr) {
    uint32_t formId = m_mem.ReadValue<uint32_t>(aFormPtr + cFormIdOffset);
    if (formId == 0) {
        std::string region = m_mem.ValidateAddress(aFormPtr);
        if (region.empty()) {
            spdlog::error("ReadFormId: ptr {:#x} is NOT in any mapped region -- Wine address translation may be needed", aFormPtr);
        } else {
            spdlog::warn("ReadFormId: ptr {:#x} is in region '{}' but formId read as 0 -- possible offset error or uninitialized form", aFormPtr, region);
        }
    }
    return formId;
}
```

if (bytesRead != sizeof(pos)) {
