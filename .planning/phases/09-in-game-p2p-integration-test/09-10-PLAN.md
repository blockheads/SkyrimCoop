<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Human verification of diagnostic output</name>
  <what-built>
Plan 09-09 added three diagnostic/fix capabilities to the native client:
1. **Startup smoke test**: Reads MZ PE header from SkyrimSE.exe base address via pread() to prove /proc/pid/mem works
2. **Deferred formId reads**: Retries ReadFormId up to 3 times with 1ms delays to work around construction timing
3. **Hex dump on failure**: Shows raw bytes at hook pointer addresses when formId reads fail

Plan 09-07 (already deployed) added essential-only hooks (6 of 31) to prevent Riverwood crash.
  </what-built>
  <how-to-verify>
    1. Run `./tests/test_ingame_sync.sh --keep-logs` (or `./deploy_and_test.sh` if preferred)
    2. Wait for Skyrim to load into Riverwood (should take ~60-90 seconds)
    3. After the native process connects, check the native process stderr log for these critical lines:

    **Check A (pread smoke test):**
    Look for "SMOKE TEST PASS" or "SMOKE TEST FAIL" in the logs.
    ```
    grep "SMOKE TEST" /tmp/skyrimcoop-test-*/native_stderr.log
    ```
    - If PASS: pread() works, Wine addresses ARE host addresses (as expected)
    - If FAIL: fundamental pread/permissions issue needs different approach

    **Check B (formId reads):**
    Look for "ReadFormIdDeferred" and "formId" messages:
    ```
    grep -i "formid\|ReadFormIdDeferred\|HexDump" /tmp/skyrimcoop-test-*/native_stderr.log | head -30
    ```
    - If "got formId 0x... on attempt 2" appears: timing fix works
    - If "formId still 0 after retries" + hex dump shows all zeros: object not constructed
    - If hex dump shows non-zero data but formId is 0: offset 0x14 may be wrong for this version

    **Check C (Skyrim stability):**
    - Did Skyrim survive past the Riverwood cell load? (essential-only hooks from 09-07)
    - How long did Skyrim stay running?

    4. Report back:
    - Paste the "SMOKE TEST" line
    - Paste 3-5 representative "ReadFormIdDeferred" or "HexDump" lines
    - Report whether Skyrim crashed or stayed running through Riverwood

    If test_ingame_sync.sh is cumbersome, alternatively:
    - Launch Skyrim manually via `proton run skse64_loader.exe`
    - Wait for relay_info.json, then launch native process manually:
      `./skyrim-coop --pid $(pgrep -f SkyrimSE.exe) --port $(grep -o '"port":[0-9]*' .../skyrim_coop_relay.json | grep -o '[0-9]*')`
    - Check stderr output directly in terminal
  </how-to-verify>
  <resume-signal>
    Paste the diagnostic output and report Skyrim stability. Based on results:
    - If SMOKE TEST PASS + formIds reading: Gap 1 is FIXED, proceed to two-instance test
    - If SMOKE TEST PASS + formIds still 0: Need to investigate offset (0x14) or try reading at CharacterCtor this+formId after constructor returns
    - If SMOKE TEST FAIL: Fundamental pread issue, need alternative memory read approach
    - If Skyrim crashes: Need to reduce hooks further or try a different hooking approach
  </resume-signal>
