**Step 3: If build fails, diagnose and fix**

Common expected issues (from RESEARCH.md pitfalls):
- **`-static` conflict:** If any target still has blanket `-static`, it will conflict with shared libs. Fix by ensuring the root xmake.lua devbuild block doesn't include `-static`.
- **Missing symbol exports:** If shared DLLs fail to link because symbols aren't found, verify `--export-all-symbols` is being passed. May need to check that `add_shflags` is used (not `add_ldflags`) for shared targets.
- **lld path not found:** If `-fuse-ld=lld` fails, check that `.toolchain/bin/ld.lld` symlink is accessible. May need to add `-B.toolchain/bin/` to the GCC command line.
- **Import lib conflicts:** The `before_link` hook in client/xmake.lua cleans stale import libs. May need to extend this pattern to other shared lib targets.
- **Circular dependencies:** If shared libs have circular deps (A needs B, B needs A), use `--allow-multiple-definition` or restructure.

Fix each error in the appropriate xmake.lua file and re-run `xmake -y` until the build succeeds.

**Step 4: Verify outputs**
```bash
# Check that the final DLL exists and is a valid PE

# Check for .dwo files (split DWARF)

# Check for internal shared DLLs
find build/ -name "*.dll" | grep -v SkyrimTogether | head -10

# Check DLL size (should be smaller than releasedbg's 13MB since -O0 but no debug info in binary)

```

**Step 5: Verify releasedbg still works (regression check)**
```bash

time xmake -y
file build/*/SkyrimTogetherClient.dll
ls -lh build/*/SkyrimTogetherClient.dll
```

Both modes must produce valid PE DLLs.
