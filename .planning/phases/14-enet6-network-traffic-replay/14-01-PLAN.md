```cpp
#pragma once
#include <nlohmann/json.hpp>
#include <Messages/Message.h>
#include <cstdint>
#include <vector>
#include <string_view>

struct MessageSerializer {
    // Serialize any ClientMessage to JSON: {"type":"AuthenticationRequest","opcode":0,"payload":"base64..."}
    static nlohmann::json ClientToJson(const ClientMessage& acMessage);
    // Serialize any ServerMessage to JSON: {"type":"AuthenticationResponse","opcode":0,"payload":"base64..."}
    static nlohmann::json ServerToJson(const ServerMessage& acMessage);

    // Deserialize JSON back to binary buffer (opcode byte + serialized payload)
    // Suitable for feeding into GameServer::InjectMessage()
    static std::vector<uint8_t> ClientFromJson(const nlohmann::json& acJson);
    static std::vector<uint8_t> ServerFromJson(const nlohmann::json& acJson);

    // Type name lookups
    static std::string_view GetClientMessageName(ClientOpcode aOpcode);
    static std::string_view GetServerMessageName(ServerOpcode aOpcode);
    static ClientOpcode GetClientOpcodeByName(std::string_view aName);
    static ServerOpcode GetServerOpcodeByName(std::string_view aName);
};
```

**Code/server/Recording/MessageSerializer.cpp**:
- Build two static arrays `s_clientNames[kClientOpcodeMax]` and `s_serverNames[kServerOpcodeMax]` using `ClientMessageFactory::Visit()` and `ServerMessageFactory::Visit()`. Inside Visit lambda, use `#define REGISTER_CLIENT_NAME(T)` style with a macro that maps `T::Opcode` to `#T`. Since Visit uses MetaMessage<T>, use a helper template: for each MetaMessage<T> in the Visit, set `names[T::Type::Opcode] = TypeName<T::Type>`. For type name extraction, define a `template<class T> struct MessageTypeName` with partial specializations generated by a macro `DEFINE_MSG_NAME(ClassName)` that sets `static constexpr const char* value = #ClassName;`.
- **Simpler approach:** Build the name arrays with a single explicit initialization function that uses Visit() + `__PRETTY_FUNCTION__` parsing is fragile. Instead, use a direct mapping approach: create a helper function `BuildClientNames()` that calls `ClientMessageFactory::Visit([&](auto meta) { ... })` where inside the lambda, `using MsgType = typename decltype(meta)::Type;` gives the message type. Then use a trait `MessageName<MsgType>` specialized per type. Generate all specializations with a macro block at the top of the .cpp file:
```cpp
#define DEF_CLIENT_MSG_NAME(T) template<> struct MessageName<T> { static constexpr const char* value = #T; };
DEF_CLIENT_MSG_NAME(AuthenticationRequest)
DEF_CLIENT_MSG_NAME(AssignCharacterRequest)
// ... all 46 client messages
// ... all 53 server messages (with DEF_SERVER_MSG_NAME or same macro)
```
- `ClientToJson()`: Call `acMessage.Serialize(writer)` to binary buffer (which writes opcode byte + SerializeRaw), then skip the first byte (opcode), base64-encode the rest as "payload", set "type" from name map, set "opcode" from `GetOpcode()`.
- Actually, use `SerializeRaw(writer)` directly (no opcode prefix) for the payload. The opcode is stored separately in JSON.
- `ClientFromJson()`: Read "opcode" int, read "payload" base64 string, decode to binary. Prepend opcode byte. Return vector suitable for `InjectMessage(data, size, connId)` which calls `OnConsume()` which calls `factory.Extract(reader)` that reads opcode first.
- Wait -- `Extract()` reads 8 bits as opcode first, then calls `DeserializeRaw()`. So the binary format for InjectMessage is: [opcode_byte][serialized_raw_payload]. So `ClientFromJson` must: decode base64 to get the raw payload, prepend the opcode byte, return that buffer.
- `ServerFromJson()` follows the same pattern for server messages.
- `GetClientOpcodeByName` / `GetServerOpcodeByName`: Linear scan of the name array (only used during replay, not hot path).
