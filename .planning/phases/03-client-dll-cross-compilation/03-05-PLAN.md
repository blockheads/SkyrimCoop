Remove --noinhibit-exec from the MinGW DLL linker flags and provide comprehensive stub implementations for ALL unresolved Skyrim engine symbols so the DLL links cleanly and does not crash during DLL_PROCESS_ATTACH.

Purpose: The current DLL crashes on load (ERROR_NOACCESS 0x3E6) because --noinhibit-exec fills unresolved symbols with null pointers that static constructors dereference. Removing this flag and providing real stubs eliminates the crash.

Output: A clean-linked SkyrimTogetherClient.dll that can be loaded by SKSE without access violations during static initialization.

  <action>
**Step 1: Remove --noinhibit-exec and attempt a build to collect ALL unresolved symbols.**

Edit `Code/client/xmake.lua` line 143: remove `"-Wl,--noinhibit-exec"` from the `add_shflags` call in the `SkyrimTogetherClientDLL` target. Keep all other flags (`-static-libgcc`, `-static-libstdc++`, `-Wl,--allow-multiple-definition`, etc.).

Then run:
```bash
xmake build SkyrimTogetherClientDLL 2>&1 | tee /tmp/link_errors.txt
```

This build WILL fail with undefined reference errors. That is expected and desired.

**Step 2: Parse the undefined references.**

Extract all unique unresolved symbol names from the linker output:
```bash
grep "undefined reference to" /tmp/link_errors.txt | sed "s/.*undefined reference to \`//" | sed "s/'.*//" | sort -u > /tmp/unresolved_symbols.txt
```

**Step 3: Categorize the unresolved symbols.** They will fall into these categories:

a. **Skyrim engine class virtual functions** — classes like `ActorValueOwner`, `IAnimationGraphManagerHolder`, and likely many more Skyrim game engine classes whose vtable entries point into SkyrimSE.exe at runtime. For these:
   - Find the header that declares the class (grep the `Code/client/Games/` directory)
   - Include that header in link_stubs.cpp
   - Provide minimal stub implementations for each unresolved virtual function (return default values: 0, nullptr, false, empty)
   - Follow the existing pattern in link_stubs.cpp for ActorValueOwner

b. **MSVC UCRT/CRT intrinsics** — functions like `__intrinsic_setjmpex`, `__local_stdio_printf_options`, etc. that come from MSVC-compiled dependencies (lua, libuv). For these:
   - Add `extern "C"` stub implementations with reasonable defaults
   - Follow the existing pattern in link_stubs.cpp

c. **Windows API functions not in MinGW import libs** — rare but possible. For these:
   - Add them to `add_syslinks` in the xmake target if they're in a standard Windows DLL
   - Or provide `extern "C"` stubs if they're MSVC-specific

d. **Static data symbols** — global variables or static class members from Skyrim headers. For these:
   - Provide zero-initialized global definitions in link_stubs.cpp

**Step 4: Rewrite `Code/client/link_stubs.cpp`** with ALL stubs discovered in Step 2-3. Keep the existing stubs that work (ActorValueOwner, IAnimationGraphManagerHolder, MSVC intrinsics) and ADD all newly discovered ones. Organize the file by category with clear section comments.

**Step 5: Rebuild and iterate.** Run `xmake build SkyrimTogetherClientDLL` again. If new undefined references appear (some symbols only surface after others are resolved), repeat Steps 2-4. Continue until the build succeeds with zero undefined references and no --noinhibit-exec.

IMPORTANT: Do NOT re-add --noinhibit-exec. The entire point is to eliminate it. Every unresolved symbol must get a real stub.

IMPORTANT: For Skyrim engine virtual functions, the stubs only need to satisfy the linker. At runtime, SKSE's address library patches the vtable to point at the real implementations in SkyrimSE.exe. The stubs will never actually be called for engine classes. They just need correct signatures and mangling.

IMPORTANT: Use `add_shflags` (not `add_ldflags`) for any new linker flags — xmake strips `add_ldflags` for shared targets.
