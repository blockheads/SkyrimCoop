    **relay_main.cpp changes:**

    1. Add includes: `#include "nlohmann/json.hpp"`, `#include "json_protocol.h"`

    2. Modify the main receive loop that currently calls `g_tcpServer.Receive(&header, payload, sizeof(payload))` to instead call `g_tcpServer.ReceiveJsonLine(msg)` where msg is `nlohmann::json`.

    3. In the receive loop, dispatch based on `msg["op"]`:
       - If op starts with "ctrl_": handle control (ctrl_heartbeat, ctrl_shutdown, ctrl_ready) same as current HandleControlPacket but reading from JSON
       - If op starts with "cmd_": enqueue to command queue. But NOTE: the SPSC command queue currently uses CommandSlot with uint64_t args[]. The DrainCommandQueue function runs on the game thread. Two approaches:
         a) Parse JSON into CommandSlot in the receive thread, enqueue binary to SPSC (preserves game-thread simplicity)
         b) Enqueue raw JSON string, parse on game thread
       - Use approach (a): parse JSON fields on receive thread, pack into existing CommandSlot struct, enqueue. This keeps DrainCommandQueue unchanged for game thread safety. The command queue is an internal DLL data structure, not a wire format.

    4. For CMD_SET_POSITION JSON parsing in the receive thread:
       ```cpp
       nlohmann::json msg;
       if (g_tcpServer.ReceiveJsonLine(msg)) {
           auto& op = msg["op"].get_ref<const std::string&>();
           if (op == JsonOp::kCmdSetPosition) {
               CommandSlot slot{};
               slot.opcode = CMD_SET_POSITION;
               slot.args[0] = msg["actor_ptr"].get<uint64_t>();
               float x = msg["x"].get<float>();
               float y = msg["y"].get<float>();
               float z = msg["z"].get<float>();
               uint32_t xBits, yBits, zBits;
               memcpy(&xBits, &x, sizeof(float));
               memcpy(&yBits, &y, sizeof(float));
               memcpy(&zBits, &z, sizeof(float));
               slot.args[1] = (static_cast<uint64_t>(yBits) << 32) | xBits;
               slot.args[2] = zBits;
               g_commandQueue.Enqueue(slot);
           }
           // ... other command ops similarly
       }
       ```
       Note: DrainCommandQueue itself does NOT change — it still reads CommandSlot binary from the SPSC queue. Only the receive-thread JSON-to-CommandSlot translation changes.

    5. For control messages received as JSON:
       - `ctrl_heartbeat`: no-op (or reset watchdog timer if exists)
       - `ctrl_shutdown`: set shutdown flag
       - `ctrl_ready`: log ready received

    6. Also update the control message SENDING. Where the DLL currently sends ControlPacket binary (e.g., CTRL_READY on startup), replace with:
       ```cpp
       nlohmann::json readyMsg = {{"op", JsonOp::kCtrlReady}};
       g_tcpServer.SendJson(readyMsg);
       ```

    7. Clear dirty cache on client disconnect:
       - Where the DLL currently handles client disconnect (in the reconnect/accept loop), call `g_dirtyCache.Clear()`
       - Add `#include "dirty_cache.h"` and `extern DirtyCache g_dirtyCache;` — OR since g_dirtyCache is file-static in hook_trampolines.cpp, either make it extern or add a separate global. Simplest: declare `extern DirtyCache g_dirtyCache;` in relay_main.cpp and change hook_trampolines.cpp from `static DirtyCache g_dirtyCache` to `DirtyCache g_dirtyCache` (non-static, with extern decl elsewhere).
