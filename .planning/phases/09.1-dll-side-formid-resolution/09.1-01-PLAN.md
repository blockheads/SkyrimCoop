<objective>
Add DLL-side formId and position reading to all hook trampolines so that resolved values (not raw Wine pointers) are sent over TCP to the native process.

Purpose: Wine guest virtual addresses are not accessible from Linux via /proc/pid/mem. The DLL runs inside Wine where these pointers are valid, so it must dereference formId (+0x14) and position (+0x54) before sending the packet. This is the root cause fix for 100% formId read failure in Phase 09.
Output: Modified hook_trampolines.cpp with ReadFormId/ReadPosition helpers and updated arg packing for all hooks. Updated protocol.h with per-opcode arg layout documentation.
</objective>

**Step 2: Add ReadFormId and ReadPosition static helpers to hook_trampolines.cpp**

Add these two functions right after the existing `FloatToU64()` helper (around line 38):

```cpp
// Safe formId read: TESForm::formID at offset +0x14
// Returns 0 if pointer is null (no crash)
static uint32_t ReadFormId(void* apForm)
{
    if (!apForm) return 0;
    return *reinterpret_cast<uint32_t*>(
        reinterpret_cast<uintptr_t>(apForm) + 0x14);
}

// Safe position read: TESObjectREFR::position (NiPoint3) at offset +0x54
static void ReadPosition(void* apRef, float* aOutX, float* aOutY, float* aOutZ)
{
    if (!apRef) { *aOutX = *aOutY = *aOutZ = 0.0f; return; }
    uintptr_t base = reinterpret_cast<uintptr_t>(apRef);
    *aOutX = *reinterpret_cast<float*>(base + 0x54);
    *aOutY = *reinterpret_cast<float*>(base + 0x58);
    *aOutZ = *reinterpret_cast<float*>(base + 0x5C);
}
```
