**Step 1: Configure and build both targets.**
```bash
cd Code/tests/feasibility
xmake f -p mingw --mingw=$HOME/.local/xPacks/@xpack-dev-tools/mingw-w64-gcc/14.3.0-1.1/.content -m release -y
xmake build gate01_skse_plugin
xmake build gate02_minhook
```
Both must exit 0. If either fails:
- Check if error is about missing C++20 features (wrong GCC version -- ensure xPack, not distro)
- Check if MinHook package fails to resolve (may need `add_requires("minhook v1.3.3", {configs = {shared = false}})`)
- Fix compilation errors in the source files from Plan 01 if needed (update main.cpp files)

**Step 2: Verify DLLs are valid PE files and statically linked.**
```bash
file build/mingw/x86_64/release/gate01_test.dll
# Must say: PE32+ executable (DLL) (console) x86-64

x86_64-w64-mingw32-objdump -p build/mingw/x86_64/release/gate01_test.dll | grep "DLL Name"
# Must NOT list libgcc_s_seh-1.dll, libstdc++-6.dll, or libwinpthread-1.dll
# Should only list KERNEL32.dll (and possibly msvcrt.dll, ntdll.dll)
```
Do the same for gate02_test.dll.

**Step 3: Verify exports exist.**
```bash
x86_64-w64-mingw32-objdump -p build/mingw/x86_64/release/gate01_test.dll | grep -E "SKSEPlugin_Query|SKSEPlugin_Load|DllMain"
# Must show SKSEPlugin_Query and SKSEPlugin_Load exports

x86_64-w64-mingw32-objdump -p build/mingw/x86_64/release/gate02_test.dll | grep "DllMain"
# DllMain may or may not appear as export (it is called by loader, not exported by name typically)
```

**Step 4: Wine smoke test.**
Test that Wine can load each DLL without crash:
```bash
WINEDEBUG=+loaddll WINEPREFIX=/tmp/gate_test_prefix wine64 rundll32 build/mingw/x86_64/release/gate01_test.dll,DllMain 2>&1 | head -20
```
Look for: DLL loads without "missing DLL" errors. It is expected that SKSEPlugin_Query/Load are NOT called (rundll32 only calls the entry point function you specify), but the DLL should load.

For gate02:
```bash
WINEDEBUG=+loaddll WINEPREFIX=/tmp/gate_test_prefix wine64 rundll32 build/mingw/x86_64/release/gate02_test.dll,DllMain 2>&1 | head -20
```
Check that MinHook initializes (look for the log file in the Wine prefix at `drive_c/gate02_minhook.log` or the working directory).

**Per D-04 fallback:** If GCC compilation fails and the error is ABI-related (not a simple code fix), document the error and note that LLVM-MinGW should be tried next. Do NOT install LLVM-MinGW in this task -- that would be a separate gap-closure plan.
