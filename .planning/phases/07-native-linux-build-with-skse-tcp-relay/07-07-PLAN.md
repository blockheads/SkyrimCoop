    **CharacterService.h / .cpp** — The core multiplayer sync service. Must handle:

    1. **Actor Lifecycle** — hook events for actor creation/destruction
       - `HOOK_ACTOR_ADDED` / `HOOK_CHARACTER_CTOR` / `HOOK_SPAWN_ACTOR`: Register new actor in pointer table, read formId via proc_memory, create ECS entity with appropriate components
       - `HOOK_ACTOR_REMOVED` / `HOOK_DEATH_ITEMS`: Remove from pointer table, destroy ECS entity

    2. **Movement Sync** (100ms tick per current code line ~1361)
       - `Update(float deltaTime)` with 100ms accumulator
       - For local player: read position/rotation via `m_reader.ReadActorPosition(playerPtr)`, compare with cached, send `ClientReferencesMoveRequest` if changed
       - For local-owned actors: same pattern, batch into single move request
       - For remote actors: receive `ServerReferencesMoveRequest`, update target position in InterpolationComponent

    3. **Animation Variables**
       - `HOOK_PERFORM_ACTION` (args: actor ptr, action event ptr): Read action data from memory, send animation variable sync
       - For remote actors: receive animation updates, send CMD_PLAY_ANIMATION to DLL for application
       - Animation variables (BehaviorVar) sync: read variable values from Actor's animation graph via memory reads

    4. **Remote Actor Management**
       - Receive `ServerAssignCharacterRequest`: allocate remote actor, set initial position via CMD_SET_POSITION
       - Receive `ServerRemoveCharacterRequest`: mark for removal
       - Track owner (local vs remote) for each actor entity

    Structure:
    ```cpp
    class CharacterService {
    public:
        CharacterService(GameReader& reader, entt::registry& registry);
        void OnHookEvent(const HookEventPacket& pkt);
        void Update(float deltaTime);

        // Network message handlers (called when messages arrive from server)
        void OnAssignCharacter(/* server message */);
        void OnRemoveCharacter(/* server message */);
        void OnReferencesMoveRequest(/* server message */);

    private:
        GameReader& m_reader;
        entt::registry& m_registry;
        float m_moveSyncTimer = 0.0f;
        static constexpr float kMoveSyncInterval = 0.1f;  // 100ms

        // Local player tracking
        uint64_t m_localPlayerPtr = 0;
        uint32_t m_localPlayerFormId = 0;

        void HandleActorAdded(uint64_t actorPtr);
        void HandleActorRemoved(uint64_t actorPtr);
        void SyncMovement();
        void SyncAnimationVars();
    };
    ```

    Key differences from current implementation:
    - Position reads: `m_reader.ReadActorPosition(actorPtr)` instead of `pActor->GetPosition()`
    - Rotation reads: `m_reader.Read<glm::vec2>(actorPtr, kRotationOffset)` instead of direct member access
    - FormId reads: `m_reader.ReadFormId(actorPtr)` instead of `pActor->formID`
    - Remote actor position application: `CMD_SET_POSITION` command to DLL instead of direct `pActor->SetPosition()`
    - Animation application: `CMD_PLAY_ANIMATION` command instead of direct function call

    The EnTT registry is instantiated in main.cpp and passed to CharacterService. Define minimal component types in the native_client:

    ```cpp
    // In a components.h or inline
    struct LocalComponent { uint32_t formId; uint64_t gamePtr; };

    struct InterpolationComponent { glm::vec3 targetPos; glm::vec3 currentPos; glm::vec2 targetRot; glm::vec2 currentRot; };
    ```

    Key changes:
    - Instead of getting a view from `World::Get()`, take `entt::registry&` as parameter

    ```cpp
    comp.currentPos = glm::mix(comp.currentPos, comp.targetPos, glm::clamp(deltaTime * kLerpSpeed, 0.0f, 1.0f));
    comp.currentRot = glm::mix(comp.currentRot, comp.targetRot, glm::clamp(deltaTime * kLerpSpeed, 0.0f, 1.0f));
    ```

    This system takes animation variable updates and sends CMD_PLAY_ANIMATION commands to the DLL for remote actors.

    ```cpp
    class AnimationSystem {
    public:
        static void Update(entt::registry& registry, TcpClient& tcp, float deltaTime);
    };
    ```

    For each entity with RemoteComponent + animation data: if animation vars changed, build CMD_PLAY_ANIMATION packet and send via TCP.

    1. Parse args (--pid, --port)
    2. Init spdlog, rpmalloc
    3. Create ProcMemReader, open for target PID
    4. Create PointerTable
    5. Create GameReader(procMem, pointerTable)
