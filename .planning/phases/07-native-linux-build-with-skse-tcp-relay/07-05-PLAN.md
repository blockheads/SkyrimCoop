    **hook_trampolines.h** — Declares `void InstallAllHooks()` and `void RemoveAllHooks()`.

    **hook_trampolines.cpp** — Implements MinHook trampoline functions for all ~30 hook types identified in the research.

    Each trampoline follows the pattern from research Pattern 1:
    ```cpp
    static TOriginalFunc* RealFunc = nullptr;
    ReturnType __fastcall HookFunc(void* apThis, ArgType1 a1, ...) {
        HookEventPacket pkt{};
        pkt.header.opcode = HOOK_XXX;
        pkt.header.length = sizeof(pkt) - sizeof(PacketHeader);
        pkt.argCount = N;
        pkt.args[0] = reinterpret_cast<uint64_t>(apThis);
        pkt.args[1] = reinterpret_cast<uint64_t>(a1);  // or bit_cast for floats
        g_tcpServer.Send(&pkt, sizeof(pkt));
        return RealFunc(apThis, a1, ...);
    }
    ```

    The DLL needs Address Library for hook target resolution. It must include the POINTER_SKYRIMSE infrastructure. Since the DLL target already depends on `SkyrimCoopHooks` and `SkyrimCoopReverse` (from Plan 02), these provide Address Library access.

    Priority hooks to implement (per research Hook Inventory):

    **Actor Lifecycle (6):** ActorProcess, SetPosition, CharacterConstructor, CharacterConstructor2, SpawnActorInWorld, AddDeathItems
    **Combat (5):** DamageActor, ApplyActorEffect, RegenAttributes, UpdateDetectionState, UpdateTarget
    **Inventory (6):** AddInventoryItem(Actor), PickUpObject, DropObject, UnequipObject, AddInventoryItem(REFR), RemoveInventoryItem
    **Magic (5):** SpellCast, InterruptCast, AddTarget, FindTargets, RemoveSpell
    **Object/World (5):** Activate, LockChange, PlayAnimation, ProjectileLaunch (RotateX/Y/Z can be deferred)
    **Weather (3):** SetWeather, ForceWeather, UpdateWeather
    **Other (3):** PerformAction, SimulateTime, InitiateMountPackage

    `InstallAllHooks()`:
    1. `MH_Initialize()` (tolerate MH_ERROR_ALREADY_INITIALIZED)
    2. For each hook: `MH_CreateHook(resolvedAddress, &HookFunc, reinterpret_cast<LPVOID*>(&RealFunc))`
    3. `MH_EnableHook(MH_ALL_HOOKS)`

    `RemoveAllHooks()`:
    1. `MH_DisableHook(MH_ALL_HOOKS)`
    2. `MH_Uninitialize()`

    Call `InstallAllHooks()` from `relay_main.cpp`'s `SKSEPlugin_Load` after TCP server starts.

    For float arguments passed through uint64_t: use `memcpy` to bit-cast float to uint64_t:
    ```cpp
    uint64_t FloatToU64(float f) {
        uint64_t v = 0;
        memcpy(&v, &f, sizeof(f));
        return v;
    }
    ```

    The hook addresses come from POINTER_SKYRIMSE macro which resolves Address Library IDs. Use the same IDs as the current codebase (e.g., Actor.cpp line 1315 uses ActorProcess at some ID, SetPosition at another). Extract the specific Address Library IDs from the existing hook installation code.

    Create `Code/native_client/Services/` directory.

    Each service follows the same rewrite pattern demonstrated in research lines 316-332:
    - BEFORE (current): Direct pointer dereference (`Sky::Get()->GetWeather()->formID`)
    - AFTER (new): GameReader memory reads (`m_reader.ReadChain<uint32_t>(skyPtr, Sky::kWeatherOffset, TESForm::kFormIdOffset)`)

    Services receive hook events via a dispatch function called from main.cpp's event loop and read game state via GameReader + ProcMemReader. They send network messages to the server using the existing SkyrimEncoding message types (which build natively).

    **WeatherService.h / .cpp** (proof of concept, simplest service):
    - Constructor takes `GameReader&` and a reference to the network transport
    - `OnHookEvent(const HookEventPacket& pkt)` — handles HOOK_SET_WEATHER, HOOK_FORCE_WEATHER
    - `Update(float deltaTime)` — periodic weather state poll (same 250ms interval as current)
    - Reads: Sky singleton pointer (known global address from Address Library), then weather formId via ReadChain
    - Sends: `ServerWeatherRequest` when weather changes (using existing encoding message)
    - Receives commands: CMD_FORCE_WEATHER → sends over TCP to DLL
    - Key offsets: Sky::kWeatherOffset, TESForm::kFormIdOffset (extract from existing game struct headers)

    **CalendarService.h / .cpp** (time sync):
    - `Update(float deltaTime)` — reads game time via memory read
    - Reads: Calendar singleton, TimeOfDay, DaysPassed
    - Sends: time sync messages
    - Very simple: just periodic memory reads + network send

    **QuestService.h / .cpp** (event forwarding):
    - Receives quest stage change hooks (adapted from HOOK_PERFORM_ACTION if quest-related)
    - Reads: quest stage from memory via quest form pointer
    - Forwards quest progress to server

    **CombatService.h / .cpp** (projectile + damage):
    - `OnHookEvent` handles HOOK_DAMAGE_ACTOR, HOOK_PROJECTILE
    - Reads: attacker/target formIds from pointer table
    - Sends: damage/projectile sync messages

    Each service class:
    ```cpp
    class WeatherService {
    public:

        // ... service-specific state
    };
    ```

    Wire services into main.cpp event loop: In main.cpp, instantiate all services after GameReader is created. In the event dispatch for hook events, call each service's `OnHookEvent`. Add a periodic `Update` call at appropriate intervals.

    Note: The network transport layer (sending messages to other players/server) reuses the existing SkyrimEncoding message types and TransportService pattern. For now, services can log what they would send rather than actually sending — the full network integration happens when CharacterService (the core movement sync) is rewritten in Plan 07.
