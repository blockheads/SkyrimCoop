    **tcp_server.h / tcp_server.cpp** — Winsock2 TCP server class for localhost.

    ```cpp
    // tcp_server.h
    #pragma once
    #include <winsock2.h>
    #include <cstdint>
    #include "protocol.h"

    class TcpServer {
    public:
        // Bind to localhost:0, listen, store assigned port. Returns true on success.
        bool Start();
        void Stop();

        // Accept a single client (blocking). Returns true when client connects.
        bool AcceptClient();

        // Send a packet to the connected client. Thread-safe (called from hook trampolines).
        bool Send(const void* data, uint32_t size);

        // Receive a packet from the client (blocking read of header, then payload).
        // Returns false on disconnect.
        bool Receive(PacketHeader* outHeader, void* outPayload, uint32_t maxPayload);

        uint16_t GetPort() const { return m_port; }
        bool IsClientConnected() const { return m_clientSocket != INVALID_SOCKET; }

    private:
        SOCKET m_listenSocket = INVALID_SOCKET;
        SOCKET m_clientSocket = INVALID_SOCKET;
        uint16_t m_port = 0;
        CRITICAL_SECTION m_sendLock;  // protects Send() from concurrent hook trampolines
    };
    ```

    Implementation details:
    - `Start()`: `WSAStartup(MAKEWORD(2,2), &wsa)`, create socket `AF_INET, SOCK_STREAM, IPPROTO_TCP`, bind to `127.0.0.1:0`, `listen(socket, 1)`, `getsockname()` to read assigned port, `InitializeCriticalSection(&m_sendLock)`. Per Pitfall 4 (port collision), always use port 0.
    - `AcceptClient()`: blocking `accept()`. Single client only.
    - `Send()`: `EnterCriticalSection(&m_sendLock)`, loop `send()` until all bytes sent, `LeaveCriticalSection`. Returns false on SOCKET_ERROR.
    - `Receive()`: read exactly `sizeof(PacketHeader)` first, then read `header.length` bytes of payload. Returns false on disconnect (recv returns 0 or error).
    - `Stop()`: `closesocket` both sockets, `DeleteCriticalSection`, `WSACleanup()`.

    **process_launcher.h / process_launcher.cpp** — Launch native ELF binary via CreateProcess.

    Per Pitfall 2 (MinGW POSIX headers), use Windows `CreateProcess` API instead of fork/exec. Wine's CreateProcess internally does fork/exec. Pass the native binary path using Wine's Z: drive mapping (`Z:\path\to\skyrim-coop`).

    Per Pitfall 7 (Wine PID), use `GetCurrentProcessId()` for the PID passed to the native process. Under Wine, `GetCurrentProcessId()` returns the Wine-internal PID. BUT the native process needs the Linux PID for /proc/pid/mem. Solution: the native process should use the Wine PID to find the real Linux PID by scanning /proc/*/comm for "SkyrimSE.exe" or by reading /proc/self/status to get the tracer info. Alternatively, the DLL can declare `extern "C" int getpid();` which resolves at runtime under Wine to the real Linux PID. Use the getpid() approach first with CreateProcess fallback.

    ```cpp
    // process_launcher.h
    #pragma once
    #include <windows.h>
    #include <cstdint>

    class ProcessLauncher {
    public:
        // Launch the native skyrim-coop binary. nativePath is the Linux path to the binary.
        // tcpPort is the port the TCP server is listening on.
        bool Launch(const char* nativePath, uint16_t tcpPort);

        // Check if the native process is still running
        bool IsAlive() const;

        // Kill the native process
        void Kill();

        // Get the spawned process handle
        HANDLE GetProcessHandle() const { return m_processInfo.hProcess; }

    private:
        PROCESS_INFORMATION m_processInfo{};
        bool m_launched = false;
    };
    ```

    Implementation:
    - Determine the Skyrim Linux PID: Declare `extern "C" int getpid(void);` and call it. This resolves at runtime under Wine to the actual Linux PID. If it fails at link time, fall back to GetCurrentProcessId() and document that the native process will need to discover the real PID via /proc enumeration.
    - Build command line: `Z:\path\to\skyrim-coop --pid <pid> --port <port>`
    - The native binary path should be derived relative to the DLL's location. Use `GetModuleFileNameA(NULL, ...)` to get the Skyrim exe path, then construct path to `skyrim-coop` in the same SKSE plugins directory or a sibling directory.
    - `CreateProcessA(NULL, cmdLine, ...)` with `CREATE_NEW_CONSOLE` flag so the native process gets its own console for logging.
    - Store PROCESS_INFORMATION for monitoring.
    - `IsAlive()`: `WaitForSingleObject(m_processInfo.hProcess, 0) == WAIT_TIMEOUT`.
    - `Kill()`: `TerminateProcess(m_processInfo.hProcess, 1)`.

    The monitor thread function:

    ```cpp
    static DWORD WINAPI MonitorThread(LPVOID) {
        while (!g_shuttingDown) {
            if (!g_tcpServer.AcceptClient()) {
                Sleep(1000);
                continue;
            }
            // Receive loop
            PacketHeader header;
            uint8_t payload[512];
            while (g_tcpServer.Receive(&header, payload, sizeof(payload))) {
                if (header.opcode >= 0x8000 && header.opcode < 0xF000) {
                    // Command from native process
                    auto* cmd = reinterpret_cast<CommandPacket*>(&header);
                    CommandSlot slot;
                    slot.opcode = cmd->header.opcode;
                    slot.argCount = cmd->argCount;
                    memcpy(slot.args, cmd->args, sizeof(slot.args));
                    g_commandQueue.Enqueue(slot);
                }
            }
            // Client disconnected -- auto-restart per D-08
            if (!g_shuttingDown) {
                g_launcher.Kill();
                Sleep(2000);
                g_launcher.Launch(/* same args */);
            }
        }
        return 0;
    }
    ```
